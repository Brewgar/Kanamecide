# E-00008 — O3c quiescence search (stand-pat, captures/promos, delta prune, check evasion)

## Hypothesis
D-0006 (quiescence-first ratified): without quiescence, every leaf eval is horizon-noisy
(pending captures are missed), so score-based comparisons — including the later O3d/E-EVAL
and SPRT gates — are uninterpretable. Adding qsearch fixes the horizon at the leaf.

## Baseline
O3b: staged ordering (PV/MVV-LVA/killers/history), alpha-beta, material-only eval, NO
quiescence (leaf returns static eval while captures are pending). Measured at depth 3+4.

## Candidate
O3c: qsearch() called at the negamax depth-0 leaf:
1. stand-pat evaluate; if >= beta, fail high (only when NOT in check)
2. generate ALL moves via the pseudo-legal generator + DEC-0008 filter; when not in check,
   keep only captures + promotions (is_capture_or_promo)
3. delta pruning: skip a capture if stand_pat + victim_value + 200 < alpha (200 cp margin;
   material-only eval exact in material, so this is generous safety)
4. check evasion: if in check, do NOT stand-pat; search ALL legal evasions; if none survives,
   return -MATE
5. same alpha-beta bound structure; recursion bounded by position (captures remove material).
   A defensive QSEARCH_MAX_PLY=512 guard is present but unreachable in legal play.

## Difference
qsearch is invoked at every negamax leaf instead of a bare evaluate(). Node count RISES
(expected: qsearch extends the search). Score accuracy improves (pending captures resolved).

## Hardware
AMD Ryzen 7 9700X (8C/16T), 32 GB DDR5-6000, Windows 11, MSVC 19.51, CMake 4.4.3.
Node counts in the Audit config (/O2 no NDEBUG; node counts are NDEBUG-independent).

## Engine Version
Post-O3c HEAD; `src/search.{h,cpp}` add `qsearch()` + compile-time `QSEARCH` (0/1);
`src/board.cpp` H-0012 guardrail refined (see Findings).

## Network
None.

## Dataset
73 positions: 70 hanging-piece (Q/R/B/N/P en prise to a cheaper/equal attacker) + 3
mate-in-1/2, all validated at load by python-chess. Generated by `gen_tactics.py` ->
`tactics_set.py`; measured by `measure_qs.py` at depth 3+4 on QSEARCH=0 (O3b) and
QSEARCH=1 (O3c) builds.

## Test Method
Per position per depth: `position fen` + `go depth D`, parse `info`+`bestmove`. Oracle:
apply bestmove to a python-chess board; pass iff the annotated victim is no longer en prise
(SAVED) or captured. For mates: bestmove checkmates OR score >= +MATE.

## Games / Samples
30 self-play games vs legal-move-uniform random at depth 4 (QSEARCH=1): 30/30 wins, 30/30
legal.

## Metrics
**Tactical pass-rate (73 positions x depth 3 AND depth 4):**
- O3b (no qsearch): 146/146 = 100%
- O3c (qsearch): 146/146 = 100%
Criterion (c) >=90% met by BOTH at these depths (simple hangs are within horizon at d3-4);
the discriminator is score accuracy:

**Score differences (13 positions where O3b != O3c; O3c higher on 12, lower on 1):**
| Position | depth | O3b | O3c | interpretation |
|---|---|---|---|---|
| hg_Q_N_d5/e4 | 3 | 20,580 | 1,000,000 | O3c FINDS the mate |
| hg_Q_B_d5/e4 | 3 | 20,570 | 1,000,000 | same |
| hg_B_B_d5/e4 | 3 | 20,000 | 1,000,000 | same |

**Node count:** O3b 168,443 vs O3c 350,626 = 2.08x (depth3 2.40x, depth4 1.98x).

## Results
(a) perft 10/10 bit-identical (Release AND Audit) PASS
(b) legal-game rate 30/30 = 100% PASS
(c) tactical pass-rate 73/73 = 100% PASS
(d) win-rate vs random 30/30 = 100% PASS
-> O3d (TT/ID/time-control) unblocked.

## Statistical Analysis
Deterministic search (no SPRT). The pass-rate does not discriminate O3b vs O3c at depth
3-4 for simple hangs (both 100%). The discriminating evidence is SCORE accuracy: O3c finds
8 mates and corrects 2 phantom overestimates at 2.08x node cost.

## Interpretation
**Decision rule verdict: PASS.** O3c is the last "correctness of the search" milestone: the
leaf is tactically resolved, so O3d TT/ID/time deltas and E-EVAL Texel will be measured on
honest scores. Node rise 2.08x is expected and good (qsearch extends the search); the O3b
node tables are pre-quiescence and should not be cited as post-O3c baselines.

## Findings
1. O3c finds 8 mate scores at depth 3 that O3b misses: qsearch's check-evasion path detects
   mate at the leaf where O3b's static eval does not. This is the concrete fixed-depth qsearch
   payoff.
2. O3c corrects 2 phantom overestimates (hg_R_P_d5 d3 O3b 500->O3c 400; wn_r_N_d4 d3+4 O3b
   180->O3c 500). O3b's static leaf overestimates because pending recaptures are unresolved.
3. Node count rises 2.08x (350,626 vs 168,443) — expected and good.
4. H-0012 assert REFINED: the original `assert(to != king_sq[enemy])` in make_move fired on
   legitimate pseudo-legal king-captures generated in CHECK positions (the DEC-0008 filter
   rejects them after make_move; the assert fired before the filter). Refined to fire only
   when the enemy is NOT already in check (a genuine generator bug). Perft 10/10 confirms
   the fix is behavior-neutral.

## Conclusion
O3c (quiescence) passes the decision rule: the leaf is tactically resolved, O3c finds mates
and corrects phantom overestimates O3b produces at fixed depth, at 2.08x node cost. O3d
(TT/ID/time-control) is unblocked.

## Follow-Up
O3d: TT + iterative deepening + time management + stop-during-search atop O3c qsearch.
E-EVAL (tapered eval + Texel) after O3d. The 73-position self-validating tactical set is
retained as a regression gate for future search changes.
